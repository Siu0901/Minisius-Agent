# ROADMAP — Minisius Agent

마일스톤 단위의 순서만 적는다. 마일스톤 안의 세부 기능과 검증 상태는
`.harness/features.json` 이 원본이다.

| 마일스톤 | 내용 | 완료 목표 |
|---|---|---|
| M0 | 개발 하네스(문서, 상태 파일, 검증 스크립트) | `./scripts/verify.sh` 가 통과한다 |
| v0.1-alpha | 예외, 메시지 포맷, 설정, 이벤트 로그, Provider 인터페이스, Anthropic 어댑터, 실행 백엔드, Tool Registry, 파일 읽기 도구, Agent Loop, CLI | 실제 모델이 파일을 읽고 답한다 |
| v0.1-beta | 최소 권한 정책과 CLI 승인, 파일 수정, 셸, 웹 도구, Gemini·OpenAI 호환 어댑터 | 터미널에서 안전하게 일을 시킨다 |
| v0.2 | Discord 게이트웨이와 승인 버튼, `setup` 온보딩, 서비스 등록, 소유자 제한, "항상 허용" 목록, 정책 설정 | 폰에서 시키고 승인한다 |
| v0.3 | 세션 저장·재개, Context Compaction | 긴 대화와 재시작을 견딘다 |
| v0.4 | 기억(메모 파일 + 세션 검색) | 지난 대화를 기억한다 |
| v0.5 | 스킬 로딩과 자가 작성 | 반복 작업이 스킬로 남는다 |
| v0.6 | 스케줄러, Planning, 중단 복구 | 예약 작업과 긴 작업을 처리한다 |
| v0.7 | MCP Client, Docker 샌드박스 | 외부 서비스 연동과 격리 실행 |
| v0.8 | 과제 20~30개 평가 | 성공률·비용·복구율을 재현 가능하게 기록한다 |

## 순서의 이유

- 이벤트 로그와 토큰 기록은 v0.1부터 넣는다. 뒤의 복구·압축·평가가 모두 이 위에 얹힌다.
- v0.1을 둘로 나눈다. alpha는 프로바이더 하나와 읽기 전용 도구로 Agent Loop가 실제로 도는 것을 먼저 확인한다. 어댑터 3개를 다 만든 뒤에야 처음 실행하면 인터페이스의 문제를 늦게 발견한다.
- 쓰기와 셸 도구는 권한 정책과 같은 단계(beta)에 넣는다. 정책 없이 위험한 도구가 먼저 생기지 않게 한다. alpha에는 읽기 전용 도구만 있다.
- alpha의 프로바이더는 Anthropic이다. thinking 블록을 그대로 되돌려 보내야 하는 가장 까다로운 요구를 먼저 겪어 메시지 포맷의 불투명 필드 설계를 일찍 검증한다.
- Discord는 주 인터페이스라서 v0.2로 당긴다. 원격에서 명령을 내리는 구조이므로 소유자 제한을 같은 버전에 묶는다.
- Docker 구현은 v0.7이지만 실행 백엔드 인터페이스는 v0.1에 둔다.

## 마일스톤 종료 조건

1. 해당 마일스톤의 모든 기능이 `features.json` 에서 `passes: true` 다.
2. `./scripts/verify.sh` 가 통과한다.
3. "완료 목표"를 실제로 실행해 확인했다.
