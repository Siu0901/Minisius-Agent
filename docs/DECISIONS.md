# DECISIONS — Minisius Agent

중요한 설계 결정과 그 이유. 새 결정은 맨 아래에 번호를 이어 추가한다.
결정을 뒤집을 때는 기존 항목을 지우지 않고 "대체됨: ADR-0XX" 를 적는다.

형식: 결정 / 이유 / 대안 / 단점

---

## ADR-001: 에이전트 프레임워크 미사용

- 결정: Agent Loop와 런타임을 순수 비동기 Python으로 직접 구현한다.
- 이유: 하네스 내부 구조를 직접 이해하는 것이 프로젝트의 목표다.
- 대안: LangGraph, LangChain 등.
- 단점: 상태 관리와 실행 복구를 직접 구현해야 한다.

## ADR-002: append-only 이벤트 로그를 뼈대로

- 결정: 모든 실행 과정을 SQLite 이벤트 로그에 쌓고, 복구·압축·추적·평가·인터페이스를 그 위에 얹는다.
- 이유: 기능 12개를 따로 만들면 상태가 여러 곳에 흩어진다. 로그 하나가 단일 진실이면 중단 지점 판정과 사후 채점이 같은 데이터에서 나온다.
- 대안: 메모리 내 대화 배열 + 기능별 별도 저장.
- 단점: 모든 상태 변화를 이벤트로 모델링해야 한다.

## ADR-003: 범용 에이전트, 미니 Hermes

- 결정: 코딩 전용이 아니라 CLI와 Discord로 말을 거는 범용 에이전트를 만든다. 핵심은 메시징 게이트웨이, 기억, 스킬, 예약 작업 네 가지다.
- 이유: 방대한 기능을 다 만들 수 없으므로 Hermes를 Hermes답게 만드는 것만 남긴다.
- 대안: 코딩 에이전트에 집중.
- 단점: 평가 과제를 여러 종류로 직접 만들어야 한다.

## ADR-004: 단일 사용자 설치형

- 결정: 사용자가 자기 기기에 설치하고 본인 API 키로 쓴다. 다중 사용자는 지원하지 않는다.
- 이유: 권한 모델이 단순해진다(소유자 하나).
- 단점: 온보딩(`setup`)과 서비스 등록 명령이 필요하다.

## ADR-005: 프로바이더 4개, 어댑터 3개

보완됨: ADR-021 (프로바이더 5개)

- 결정: `anthropic`, `gemini`, `openrouter`, `ollama` 를 고를 수 있게 하고, 구현은 Anthropic·Gemini 네이티브 어댑터와 OpenAI 호환 어댑터(OpenRouter, Ollama 공용) 세 개로 묶는다.
- 이유: OpenRouter와 Ollama는 `base_url` 기본값과 키 필수 여부만 다르다.
- 대안: OpenAI 호환 하나로 통일.
- 단점: 어댑터마다 도구 호출·스트리밍·thinking 처리 차이를 맞춰야 한다.

## ADR-006: 내부 표준 메시지 포맷

- 결정: 런타임과 이벤트 로그는 자체 메시지 포맷만 쓴다. 프로바이더 원본은 불투명 필드에 보존한다.
- 이유: 특정 프로바이더 포맷을 표준으로 삼으면 나머지가 계속 끼워 맞춰진다. thinking 블록 등은 그대로 되돌려 보내야 도구 루프가 깨지지 않는다.

## ADR-007: 저장소는 SQLite 하나

- 결정: 이벤트 로그, 세션, 예약 작업, 검색(FTS)을 SQLite 한 파일에 둔다.
- 이유: 단일 사용자라 PostgreSQL, Redis, 벡터 DB가 필요 없다.
- 단점: CLI와 게이트웨이의 동시 접근을 WAL 모드로 처리해야 한다.

## ADR-008: 기억과 스킬은 파일로

- 결정: 기억(`USER.md`, `MEMORY.md`)과 스킬(`SKILL.md`)은 DB가 아니라 데이터 폴더의 파일로 둔다.
- 이유: 사용자가 직접 열어 고칠 수 있어야 하고, 에이전트도 파일 도구로 다룰 수 있다.

## ADR-009: 스킬 자가 작성 포함

- 결정: 에이전트가 작업 후 스킬을 직접 쓰고 고친다.
- 이유: Hermes의 가장 큰 특징이다.
- 단점: v0.5의 범위가 커진다. 트리거와 검증 방법은 미정.

## ADR-010: CLI와 Discord는 동등한 어댑터

- 결정: 둘 다 같은 런타임에 붙고, 승인도 같은 "요청 이벤트 → 응답 이벤트" 경로를 쓴다.
- 이유: 인터페이스마다 로직이 갈라지면 한쪽만 되는 기능이 생긴다.

## ADR-011: 데이터 폴더와 작업 폴더 분리, 기본 권한 정책

- 결정: 데이터 폴더는 `~/.minisius/`. 작업 폴더는 CLI는 실행한 폴더, Discord는 `~/minisius-workspace/`. 읽기는 넓게, 수정은 작업 폴더 안만 자동, 삭제·셸은 승인.
- 이유: Discord 기본값이 홈 전체면 승인 없이 수정 가능한 범위가 컴퓨터 대부분이 된다.

## ADR-012: 실행 백엔드는 local과 docker

- 결정: 셸·파일 도구는 ExecutionBackend 인터페이스를 거친다. 구현은 `local`(기본)과 `docker` 둘.
- 이유: 서버에 설치하는 사용자는 기기 자체가 격리 역할을 하고, 개인 컴퓨터에 설치하는 사용자는 Docker를 고를 수 있다.
- 범위 밖: SSH·클라우드 백엔드. 인터페이스가 있으므로 나중에 추가할 수 있다.

## ADR-013: 오류는 세 군데에서 처리

- 결정: 예외 계층은 `errors.py` 한 파일. 도구 오류는 Registry가 도구 결과로 바꾸고, 프로바이더 오류는 어댑터와 루프가, 나머지는 인터페이스가 처리한다.
- 이유: 에이전트에서는 오류를 누구에게 돌려주느냐가 핵심이다. 도구 오류는 LLM이 읽고 스스로 고친다.

## ADR-014: Python 3.12+, uv

- 결정: Python 3.12 이상, 패키지 관리는 uv.
- 이유: 설치형이므로 지원 버전을 너무 높이지 않는다.

## ADR-015: 스트리밍을 처음부터

- 결정: Provider 의 추상 메서드는 `stream()` 하나다. 텍스트 조각을 내보내다가 마지막에 완성된 응답을 한 번 내보낸다.
- 이유: 나중에 추가하면 어댑터 3개, 루프, 인터페이스를 모두 고쳐야 한다. Discord 에서 긴 응답을 기다리게 하지 않으려면 어차피 필요하다.
- 대안: `complete()` 로 시작하고 나중에 스트리밍 추가.
- 단점: v0.1 의 어댑터 작업량이 늘어난다.

## ADR-016: 도구가 Action 을 선언하고 정책이 판정한다

- 결정: 도구는 `actions(args)` 로 무엇을 건드리는지 사실만 선언한다. `policy` 는 Action 만 보고 허용·승인·차단을 판정한다. 둘을 잇는 것은 Agent Loop 다. LLM 은 이 과정에 관여하지 않는다.
- 이유: 정책이 도구 이름과 인수를 직접 해석하면 도구를 추가할 때마다 정책을 고쳐야 하고, 빠뜨리면 검사 없이 실행된다. 검사를 LLM 이 손댈 수 없는 코드에 두어야 LLM 의 실수나 주입된 지시가 검사를 건너뛰지 못한다.
- 대안: 정책이 도구별로 인수를 해석.
- 단점: 도구가 거짓으로 선언하면 속는다. 내장 도구는 테스트로 확인하고, 내용을 알 수 없는 MCP 도구는 `EXTERNAL` 로 분류해 기본값을 승인 필요로 둔다.

## ADR-017: 이미지 입력은 넣지 않는다

- 결정: 메시지 포맷에 이미지 파트를 두지 않는다.
- 이유: v0.1 의 범위를 줄인다. `Part` 유니온에 나중에 추가할 수 있는 구조다.

## ADR-018: 최소 권한 정책을 v0.1-beta 로 당긴다

- 결정: 민감 경로 차단, 작업 폴더 밖 수정·삭제·셸의 승인, 실제 경로 판정, 셸 타임아웃과 출력 제한을 쓰기·셸 도구와 같은 단계에 넣는다. Discord 버튼, "항상 허용" 목록, 설정으로 조정하는 기능은 v0.2 에 남긴다.
- 이유: 처음 계획은 정책이 v0.2 였는데, 그러면 v0.1 만 끝나도 LLM 이 승인 없이 셸 명령을 실행한다. 도구가 Action 을 선언하는 구조(ADR-016)가 있어서 최소 정책은 판정 함수 하나와 CLI 프롬프트면 된다.
- 유지한 것: 읽기는 작업 폴더로 제한하지 않는다. 범용 에이전트라서 넓게 열고 민감 경로만 막는다(ADR-011).
- 한계: 경로 검사로는 셸 명령을 가둘 수 없다. 그래서 셸은 항상 승인이고, 격리가 필요하면 `docker` 백엔드를 쓴다.

## ADR-019: v0.1 을 alpha 와 beta 로 나누고 Anthropic 부터

- 결정: alpha 는 프로바이더 하나(Anthropic)와 읽기 전용 도구로 Agent Loop 를 실제로 돌린다. beta 에서 정책, 쓰기·셸·웹 도구, 나머지 어댑터 2개를 넣는다. 이벤트 로그는 alpha 에 둔다.
- 이유: 어댑터 3개를 다 만든 뒤에야 처음 실행하면 인터페이스의 문제를 늦게 발견한다. 이벤트 로그를 미루지 않는 것은 루프가 처음부터 이벤트를 기록하며 돌아야 하고, 나중에 끼워 넣으면 루프를 다시 써야 하기 때문이다.
- Anthropic 을 먼저 하는 이유: thinking 블록을 그대로 되돌려 보내야 하는 요구가 있어서 메시지 포맷의 불투명 필드 설계를 가장 일찍 검증한다.
- 대안: OpenAI 호환 어댑터를 먼저(프로바이더 2개를 한 번에 덮는다).

## ADR-020: 결과가 불확실한 도구 호출은 자동 재실행하지 않는다

- 결정: `tool_call_started` 만 있고 `tool_call_finished` 가 없는 호출은 "실행 안 됨"이 아니라 "결과를 모름"으로 다룬다. 자동으로 다시 실행하지 않는다.
- 이유: 파일 수정은 끝났는데 결과 기록 전에 프로세스가 죽을 수 있다. 로그만으로는 구분할 수 없고, 다시 실행하면 같은 변경이 두 번 적용될 수 있다.
- 미정: 현재 상태를 확인하거나 사용자에게 묻는 구체적인 복구 방법(v0.6).

## ADR-021: openai 를 다섯 번째 프로바이더로

- 결정: 프로바이더에 `openai` 를 추가한다. 어댑터는 늘리지 않고 `OpenAICompatibleAdapter` 가 OpenAI, OpenRouter, Ollama 를 함께 맡는다.
- 이유: OpenAI 키만 가진 사용자가 OpenRouter 를 거치지 않고 쓸 수 있다. 어댑터가 이미 있어서 `base_url` 기본값 하나를 더하는 정도다.
- 보완하는 결정: ADR-005.

## ADR-022: 설정은 config.toml, 비밀 값은 .env

- 결정: 설정은 `config.toml`, API 키와 토큰은 데이터 폴더의 `.env` 에 둔다. 같은 이름의 환경 변수가 `.env` 보다 우선한다. `.env` 의 권한이 느슨하면 경고만 한다.
- 이유: 설정은 숫자, 목록, 묶음이 필요해서 TOML 이 맞다. 비밀 값은 이름과 값의 나열이라 `.env` 로 충분하고, 익숙한 형식이며, 환경 변수와 이름이 같아져서 "`.env` 는 환경 변수의 기본값"으로 이해할 수 있다. 서버와 Docker 에서는 환경 변수로 키를 넣는 것이 일반적이다.
- 대안: 처음 안은 `secrets.toml` 이었다. 전부 `.env` 로 하는 안은 권한 정책 같은 구조 있는 설정을 담기 어렵다.
- 권한을 경고로 둔 이유: 직접 파일을 만드는 단계에서는 매번 막히면 번거롭다. v0.2 의 `setup` 이 파일을 600 으로 만든다.
- 의존성: `python-dotenv` 를 추가했다. TOML 은 표준 라이브러리로 읽는다.

## ADR-023: Action 타입은 core 에 둔다

- 결정: `Action`, `ActionKind` 를 `tools/base.py` 가 아니라 `core/actions.py` 에 둔다.
- 이유: 도구(선언), 정책(판정), 이벤트 로그(기록), 인터페이스(승인 화면)가 모두 쓴다. `tools` 에 두면 `core/events.py` 가 `tools` 를 import 해야 하고, 이벤트 타입이 도구 계층에 묶인다.
- 보완하는 결정: ADR-016.

## ADR-024: 이벤트 로그는 표 하나, 표준 라이브러리 sqlite3

- 결정: 이벤트는 `events` 표 하나에 `(session_id, seq)` 를 키로 쌓고 payload 는 JSON 으로 둔다. `UPDATE`, `DELETE`, 같은 번호를 덮어쓰는 `INSERT` 는 DB 트리거로 거절한다. `sqlite3` 를 작업 스레드에서 호출하고 `aiosqlite` 는 추가하지 않는다.
- 이유: 이벤트 타입이 늘어도 스키마를 바꾸지 않는다. 추가만 가능하다는 규칙을 코드의 약속이 아니라 DB 가 강제한다. `aiosqlite` 가 하는 일도 스레드에서 `sqlite3` 를 부르는 것이라 의존성을 늘릴 이유가 없다.
- 번호: `append()` 가 `BEGIN IMMEDIATE` 로 쓰기 잠금을 잡은 뒤 `MAX(seq) + 1` 을 매긴다. CLI 와 게이트웨이가 같은 DB 를 써도 겹치지 않는다.
- 단점: payload 안의 값으로 검색하려면 JSON 함수를 써야 한다. 세션 검색(v0.4)은 FTS 표를 따로 둔다.
- 한계: 도구 인수와 결과를 걸러내지 않고 기록한다. 비밀 값이 들어가면 DB 에 남는다(`docs/ARCHITECTURE.md` 9절).
