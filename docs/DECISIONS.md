# DECISIONS — Minisius Agent

중요한 설계 결정과 그 이유. 새 결정은 맨 아래에 번호를 이어 추가한다.
결정을 뒤집을 때는 기존 항목을 지우지 않고 "대체됨: ADR-0XX" 를 적는다.

형식: 결정 / 이유 / 대안 / 단점

---

## ADR-001: 에이전트 프레임워크 미사용

- 결정: Agent Loop와 런타임을 순수 비동기 Python으로 직접 구현한다.
- 이유: 하네스 내부 구조를 직접 이해하는 것이 프로젝트의 목표다.
- 대안: LangGraph, LangChain 등.
- 단점: 상태 관리와 실행 복구를 직접 구현해야 한다.

## ADR-002: append-only 이벤트 로그를 뼈대로

- 결정: 모든 실행 과정을 SQLite 이벤트 로그에 쌓고, 복구·압축·추적·평가·인터페이스를 그 위에 얹는다.
- 이유: 기능 12개를 따로 만들면 상태가 여러 곳에 흩어진다. 로그 하나가 단일 진실이면 중단 지점 판정과 사후 채점이 같은 데이터에서 나온다.
- 대안: 메모리 내 대화 배열 + 기능별 별도 저장.
- 단점: 모든 상태 변화를 이벤트로 모델링해야 한다.

## ADR-003: 범용 에이전트, 미니 Hermes

- 결정: 코딩 전용이 아니라 CLI와 Discord로 말을 거는 범용 에이전트를 만든다. 핵심은 메시징 게이트웨이, 기억, 스킬, 예약 작업 네 가지다.
- 이유: 방대한 기능을 다 만들 수 없으므로 Hermes를 Hermes답게 만드는 것만 남긴다.
- 대안: 코딩 에이전트에 집중.
- 단점: 평가 과제를 여러 종류로 직접 만들어야 한다.

## ADR-004: 단일 사용자 설치형

- 결정: 사용자가 자기 기기에 설치하고 본인 API 키로 쓴다. 다중 사용자는 지원하지 않는다.
- 이유: 권한 모델이 단순해진다(소유자 하나).
- 단점: 온보딩(`setup`)과 서비스 등록 명령이 필요하다.

## ADR-005: 프로바이더 4개, 어댑터 3개

- 결정: `anthropic`, `gemini`, `openrouter`, `ollama` 를 고를 수 있게 하고, 구현은 Anthropic·Gemini 네이티브 어댑터와 OpenAI 호환 어댑터(OpenRouter, Ollama 공용) 세 개로 묶는다.
- 이유: OpenRouter와 Ollama는 `base_url` 기본값과 키 필수 여부만 다르다.
- 대안: OpenAI 호환 하나로 통일.
- 단점: 어댑터마다 도구 호출·스트리밍·thinking 처리 차이를 맞춰야 한다.

## ADR-006: 내부 표준 메시지 포맷

- 결정: 런타임과 이벤트 로그는 자체 메시지 포맷만 쓴다. 프로바이더 원본은 불투명 필드에 보존한다.
- 이유: 특정 프로바이더 포맷을 표준으로 삼으면 나머지가 계속 끼워 맞춰진다. thinking 블록 등은 그대로 되돌려 보내야 도구 루프가 깨지지 않는다.

## ADR-007: 저장소는 SQLite 하나

- 결정: 이벤트 로그, 세션, 예약 작업, 검색(FTS)을 SQLite 한 파일에 둔다.
- 이유: 단일 사용자라 PostgreSQL, Redis, 벡터 DB가 필요 없다.
- 단점: CLI와 게이트웨이의 동시 접근을 WAL 모드로 처리해야 한다.

## ADR-008: 기억과 스킬은 파일로

- 결정: 기억(`USER.md`, `MEMORY.md`)과 스킬(`SKILL.md`)은 DB가 아니라 데이터 폴더의 파일로 둔다.
- 이유: 사용자가 직접 열어 고칠 수 있어야 하고, 에이전트도 파일 도구로 다룰 수 있다.

## ADR-009: 스킬 자가 작성 포함

- 결정: 에이전트가 작업 후 스킬을 직접 쓰고 고친다.
- 이유: Hermes의 가장 큰 특징이다.
- 단점: v0.5의 범위가 커진다. 트리거와 검증 방법은 미정.

## ADR-010: CLI와 Discord는 동등한 어댑터

- 결정: 둘 다 같은 런타임에 붙고, 승인도 같은 "요청 이벤트 → 응답 이벤트" 경로를 쓴다.
- 이유: 인터페이스마다 로직이 갈라지면 한쪽만 되는 기능이 생긴다.

## ADR-011: 데이터 폴더와 작업 폴더 분리, 기본 권한 정책

- 결정: 데이터 폴더는 `~/.minisius/`. 작업 폴더는 CLI는 실행한 폴더, Discord는 `~/minisius-workspace/`. 읽기는 넓게, 수정은 작업 폴더 안만 자동, 삭제·셸은 승인.
- 이유: Discord 기본값이 홈 전체면 승인 없이 수정 가능한 범위가 컴퓨터 대부분이 된다.

## ADR-012: 실행 백엔드는 local과 docker

- 결정: 셸·파일 도구는 ExecutionBackend 인터페이스를 거친다. 구현은 `local`(기본)과 `docker` 둘.
- 이유: 서버에 설치하는 사용자는 기기 자체가 격리 역할을 하고, 개인 컴퓨터에 설치하는 사용자는 Docker를 고를 수 있다.
- 범위 밖: SSH·클라우드 백엔드. 인터페이스가 있으므로 나중에 추가할 수 있다.

## ADR-013: 오류는 세 군데에서 처리

- 결정: 예외 계층은 `errors.py` 한 파일. 도구 오류는 Registry가 도구 결과로 바꾸고, 프로바이더 오류는 어댑터와 루프가, 나머지는 인터페이스가 처리한다.
- 이유: 에이전트에서는 오류를 누구에게 돌려주느냐가 핵심이다. 도구 오류는 LLM이 읽고 스스로 고친다.

## ADR-014: Python 3.12+, uv

- 결정: Python 3.12 이상, 패키지 관리는 uv.
- 이유: 설치형이므로 지원 버전을 너무 높이지 않는다.
